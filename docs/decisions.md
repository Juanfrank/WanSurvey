# Decisions and assumptions

Where the spec was ambiguous, we chose what a field-survey operations manager would expect and recorded it here.

## Platform

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Why                                                                                                                                                                                                                                   |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | **NestJS** (not Fastify) for the API.                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Guards map directly to RBAC; DI and OpenAPI come built in.                                                                                                                                                                            |
| D2  | The API runs as **ESM**, built with `tsc`. Tests use SWC through `unplugin-swc`.                                                                                                                                                                                                                                                                                                                                                                                                                | It shares the ESM `packages/*` builds with browsers. esbuild cannot emit the decorator metadata Nest needs.                                                                                                                           |
| D3  | IDs are **UUIDv7**, generated by the app rather than by Postgres.                                                                                                                                                                                                                                                                                                                                                                                                                               | They sort by time, and tablets can create them offline. Postgres 16 has no native `uuidv7()`.                                                                                                                                         |
| D4  | **Accounts are global and multi-organisation.** An e-mail is unique across the platform and identifies one account. A `tenant_members` row links the account to each organisation and carries that organisation's status (invited, active, deactivated) and profile fields (ID code, extension). Login takes only the e-mail and password; the organisation used last opens by default, and `POST /auth/switch-tenant` moves to another one. _(Changed from one tenant per user after review.)_ | Interviewers and supervisors often work for several agencies; one account and one 2FA device serve all of them. Each session still belongs to exactly one organisation, so RLS always has a single tenant context.                    |
| D5  | Tenant isolation uses Postgres **RLS** with `FORCE ROW LEVEL SECURITY`. The app connects as `wansurvey_app`, a non-owner role with `NOBYPASSRLS`. Each request runs inside `withTenant(tenantId)`, which calls `set_config('app.tenant_id', …, true)` for that transaction only.                                                                                                                                                                                                                | Isolation still holds if application code forgets a `WHERE tenant_id`.                                                                                                                                                                |
| D6  | Login-time lookups go through `SECURITY DEFINER` functions (`auth_user_by_email`, `user_id_by_email`, `user_tenants`, `revoke_user_sessions`). `users` has its own RLS: a row is visible to the person (`app.user_id`) and to organisations they belong to, and only the person can update it. The session cookie is `<tenantId>.<token>`. Invitation and reset tokens are global and hashed; invitations record their organisation.                                                            | No tenant context exists before login. An organisation admin must never be able to change a password or 2FA secret shared with other organisations. A forged cookie prefix fails because RLS hides the session in every other tenant. |
| D7  | Sessions use opaque random tokens in an `httpOnly`, `SameSite=Lax` cookie. Only the SHA-256 of a token is stored. Defaults: 60 min idle timeout and 12 h absolute lifetime, both configurable.                                                                                                                                                                                                                                                                                                  | The spec asks for cookie sessions. Server-side revocation makes forced logout instant.                                                                                                                                                |
| D8  | CSRF uses a **synchronizer token**. The per-session token is returned at login, set in a readable `ws_csrf` cookie, and must be echoed in `X-CSRF-Token` on every non-GET request.                                                                                                                                                                                                                                                                                                              | Combined with SameSite this is standard practice, and it needs no extra storage.                                                                                                                                                      |
| D9  | TOTP is implemented in-house (RFC 6238, SHA-1, 6 digits, ±1 step). Secrets are encrypted at rest with AES-256-GCM using `APP_ENCRYPTION_KEY`. Owners and admins get an `enroll` session state: every route except 2FA setup, `me` and logout returns `MFA_ENROLLMENT_REQUIRED` until they enrol.                                                                                                                                                                                                | The logic fits in about 40 lines and is tested against our own HOTP. This avoids a dependency whose API changed recently.                                                                                                             |
| D10 | Unknown e-mails, wrong passwords and inactive accounts all return the same `INVALID_CREDENTIALS` error, and a dummy Argon2 verify keeps timing uniform. Failures are audited in every organisation of the account. Asking for an organisation the person does not belong to (after a correct password) returns `NOT_A_MEMBER`.                                                                                                                                                                  | Prevents account enumeration; the organisation list is only revealed to its owner.                                                                                                                                                    |
| D11 | **Roles** are granted through memberships. `project_id = null` means tenant-wide; a set `project_id` limits the role to that project. Tenant-level endpoints only honour tenant-wide grants. List endpoints (`GET /projects`) accept a grant in any project and then filter.                                                                                                                                                                                                                    | Spec §7 says roles are "per tenant and optionally narrowed per project".                                                                                                                                                              |
| D12 | Role changes cannot grant a role ranked above the actor's own. Only owners grant or modify owners. Users cannot change their own roles or deactivate themselves.                                                                                                                                                                                                                                                                                                                                | Prevents privilege escalation and accidental lockout.                                                                                                                                                                                 |
| D13 | Reviewers do not get `interviews.correct` by default; supervisors do.                                                                                                                                                                                                                                                                                                                                                                                                                           | The spec says "reviewers _with permission_ may edit". A per-user grant can be added later.                                                                                                                                            |
| D14 | The audit log is append-only twice over: the app role has only `SELECT` and `INSERT` on it, and a trigger rejects `UPDATE`, `DELETE` and `TRUNCATE` even for the owner role.                                                                                                                                                                                                                                                                                                                    | Spec §12 requires an immutable log.                                                                                                                                                                                                   |
| D15 | Mail goes through a `Mailer` port, with console (dev) and in-memory (tests) adapters. Real providers (SES, Postmark, SendGrid, SMTP) arrive with slice 9. Every message carries an idempotency key.                                                                                                                                                                                                                                                                                             | The spec asks for provider-agnostic mail. Adding real providers before slice 9 is not needed.                                                                                                                                         |
| D16 | OpenTelemetry and Sentry are config-gated stubs that only log a warning when configured. They get wired in slice 13.                                                                                                                                                                                                                                                                                                                                                                            | Keeps the call sites stable without shipping half-configured exporters.                                                                                                                                                               |

| D17 | **Microsoft Entra ID (Azure AD) sign-in is configured per organisation.** Each organisation links its own Entra tenant (directory id, client id, encrypted client secret). The flow is OpenID Connect authorization code with PKCE. The ID token is verified with Microsoft's published keys: issuer, audience, expiry, nonce, and `tid` equal to the configured tenant. | Agencies keep control of their own directory, MFA and Conditional Access. See `docs/sso-entra.md`. _Decided in review._ |
| D18 | **First Microsoft sign-in creates the account with no role.** The person becomes an active member without roles, `/auth/me` reports `access.state = "no_role"` with an explanatory message, owners and admins are e-mailed, and `GET /users` flags `awaitingRole`. Linking or creating by e-mail is allowed only for the organisation's `allowedDomains`; afterwards the Entra `oid` link is used. | The user asked for automatic accounts with an "empty" page until a role is assigned. Restricting to listed domains stops a guest or other-tenant account from claiming someone's e-mail. The page itself is rendered by the web app (slice 3). |
| D19 | **Microsoft MFA is trusted.** When the ID token's `amr` claim contains `mfa`, WanSurvey's own TOTP step is skipped; otherwise the normal TOTP rules apply. | Avoids double prompts while keeping a second factor for owners and admins when Microsoft did not perform MFA. _Decided in review._ |
| D20 | **Enforcement is optional per organisation.** With `enforceSso`, password sign-in to that organisation is refused (`SSO_REQUIRED`, with the start URL), except for its owners, who keep a break-glass password. Password login opens another organisation when one allows it. Switching into an enforced organisation needs an SSO session from the same Entra tenant. | Matches the user's choice and keeps a recovery route if the Entra configuration breaks. |
| D21 | Sign-in state (state, nonce, PKCE verifier, organisation, return path) lives in an **encrypted, httpOnly, 10-minute cookie** scoped to `/api/v1/auth/sso`. The return path must be a same-site relative path. | No server-side state table; tampering or reuse fails. Prevents open redirects. |

## Questionnaire and logic

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Why                                                                                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L1  | Special answers are stored as tagged values: `{"$special":"DK"}`, `{"$special":"RF"}`, `{"$special":"NA"}`. They map to codes from questionnaire settings, with defaults −8 DK, −9 RF and −7 NA.                                                                                                                                                                                                                                                                                                                                                                                                  | One representation works for every question type, including text and dates. Exports map them to the configured codes.                                                                                                         |
| L2  | **Null semantics:** any comparison (`== != < <= > >=`, `in`, `between`) involving an unanswered or special value is `false`, including `!=`. Arithmetic involving null yields null. Division by zero yields null. Nothing throws.                                                                                                                                                                                                                                                                                                                                                                 | This is what the spec requires. It keeps skips conservative: a condition never fires on missing data. Confirmed in review.                                                                                                    |
| L3  | `Q == null` and `Q != null` are explicit "unanswered / answered" tests, the one exception to L2. DK and RF count as answered.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Without the exception, `== null` would always be false, which is a trap. `answered(Q)` is the recommended form.                                                                                                               |
| L4  | `between a and b` is inclusive. `X in (…)` on a multi-choice answer is true when **any** selected code is listed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | This is how ops staff read these expressions. Confirmed in review.                                                                                                                                                            |
| L5  | Codes compare loosely across number and string (`1 == "1"`), because CSV sample data arrives as strings.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Prevents silent skip failures on imported data. Confirmed in review.                                                                                                                                                          |
| L6  | Empty strings and empty selections count as unanswered.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | A cleared field must not satisfy `answered()`.                                                                                                                                                                                |
| L7  | Yes/No questions store **codes 1 = Yes and 2 = No** by default, overridable with explicit options. _Confirmed in review._                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | This is survey convention, and SPSS and Stata exports expect codes.                                                                                                                                                           |
| L8  | Roster rows are **1-based** (`HH[1]`). Inside a roster, a variable name refers to the current row. Outside, use `HH[n].X`, `any(HH, …)`, `all(HH, …)`, or the column projection `HH.X`, which returns an array: `sum(HH.INCOME)`, `count(HH.SEX, 2)`. `index` is the current row number.                                                                                                                                                                                                                                                                                                          | These are the questionnaire designer's mental model.                                                                                                                                                                          |
| L9  | Skips are evaluated after a question is answered, and the first matching rule wins. A target must lie later in the same roster scope (skips only go forward). `END_ROW` finishes the current roster row and `END` finishes the questionnaire (as a complete). Crossing a roster boundary is a publish error.                                                                                                                                                                                                                                                                                      | Keeps routing well defined per row. Confirmed in review: forward only, first match wins.                                                                                                                                      |
| L10 | When answers fall off the path they are **moved to a stash**, logged as `path_change` events, and reported to the caller. If the path returns, they are **restored automatically** and logged as `path_restored`. _Confirmed in review._                                                                                                                                                                                                                                                                                                                                                          | The spec says cleared values must be recoverable. Re-asking 20 answers because of one mis-keyed code is the worse outcome in the field.                                                                                       |
| L11 | **Prefill** (`set Q6 = case.region`) applies once, when the question first appears on the path unanswered. If the interviewer then clears or changes it, it stays that way, but the question offers **Restore the prefilled value**, which re-applies the expression and logs a `prefill_restored` change.                                                                                                                                                                                                                                                                                        | Matches the behaviour of "Assignment on entry". The restore option was asked for in review.                                                                                                                                   |
| L12 | **Unreachable items** are publish **errors**. This covers a constant-false `showIf`, items behind an unconditional skip, and items after an unconditional end. _Confirmed in review._                                                                                                                                                                                                                                                                                                                                                                                                             | The spec lists them as static-analysis checks that block publishing. Constant `show if false` is not a supported way to disable an item.                                                                                      |
| L13 | Unknown-code comparisons (`A == 7` when 7 is not an option) and missing translations (an empty or absent text in a questionnaire language) are **errors** and block publishing.                                                                                                                                                                                                                                                                                                                                                                                                                   | Changed in review: both are almost always mistakes by the time a version is published. They show while drafting like any other error.                                                                                         |
| L14 | The option order for `randomizeOptions` is seeded by interview id and question key. `fixedPosition` options stay in place.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | The order is deterministic and identical on client, server and replay.                                                                                                                                                        |
| L15 | Pipes resolve to a visible `[EXPR]` placeholder when unresolved. Callers can pass a different placeholder (for example a blank in live CAWI).                                                                                                                                                                                                                                                                                                                                                                                                                                                     | The spec asks for visible placeholders in preview.                                                                                                                                                                            |
| L16 | Quotas are checked after each answer to a variable the quota condition reads, through an injected `QuotaProvider`. Server-side counting arrives with slice 12.                                                                                                                                                                                                                                                                                                                                                                                                                                    | Keeps the engine pure.                                                                                                                                                                                                        |
| L17 | `today()` is fixed per interview session from an injected clock. Date maths uses UTC.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Determinism between devices and the server, across timezones.                                                                                                                                                                 |
| L18 | Additions to the spec's function list: `date()`, `round()`, `abs()`. The aliases `= <> && \|\| !` are accepted for `== != and or not`. _Approved in review._                                                                                                                                                                                                                                                                                                                                                                                                                                      | Small conveniences for power users (BMI rounding, CSPro habits).                                                                                                                                                              |
| L19 | Validation, analyzer, scenario-check and mapping messages carry a stable message id and parameters (`msg`). The client translates them from its catalogue and falls back to the English `message`. Custom rule messages are localised and piped.                                                                                                                                                                                                                                                                                                                                                  | Decided in review. A unit test checks that every id the engine can produce has English and Spanish text.                                                                                                                      |
| L20 | The server re-runs routing with `verifySubmission`. Any difference in path keys, or any answer that sits off the server's path, flags a mismatch for review.                                                                                                                                                                                                                                                                                                                                                                                                                                      | Spec §5.3, determinism.                                                                                                                                                                                                       |
| L21 | **PAPI in slice 3 is a print-style preview** (`PaperForm`): numbered questions, codes beside options, answer boxes, show-if and skips printed as plain-language instructions, rosters as tables. Pipes print as «NAME». PDF generation and data entry come in slice 10 and reuse this layout.                                                                                                                                                                                                                                                                                                     | Decided in review.                                                                                                                                                                                                            |
| L22 | **Scenarios** (`Scenario` in `@wansurvey/schema`) record mode, language, test case data, the date, full quota cells, the ordered steps (answers and added roster rows), and expectations: path, outcome, disposition, answers, clears and errors. The preview saves them in the browser and as downloadable JSON until questionnaires are stored (slice 4), which will run them on publish.                                                                                                                                                                                                       | Spec §5.3 asks for saved test scenarios that run as regression tests.                                                                                                                                                         |
| L23 | **The interface is in Spanish by default, with English available** (i18next, language switch in the header, choice remembered on the device). Built-in messages are translated in the client by id (L19). The interface language is independent of the questionnaire's (L43).                                                                                                                                                                                                                                                                                                                     | Changed after slice 6: the default application language is Spanish.                                                                                                                                                           |
| L24 | **Until slice 4, the preview loads samples or a JSON file** and compiles them in the browser.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Decided in review; no API storage yet.                                                                                                                                                                                        |
| L25 | **Keyboard subset from §11 in slice 3:** digits (including multi-digit codes typed quickly), Space, Enter, Shift+Enter / Alt+←, F7/F8. Focus moves to each new question. Ctrl+M, Ctrl+G, Ctrl+P, `?` and the configurable shortcut map come with the full interviewer screen (slice 6).                                                                                                                                                                                                                                                                                                           | Covers what an interview needs; the rest depends on notes, search and pause, which do not exist yet. Slice 6 added Ctrl+M (note), Ctrl+G (go to a section), Ctrl+P (pause) and `?` (shortcut list) on the interviewer screen. |
| L26 | **One draft per questionnaire, saved even when invalid**, with a revision number. Saves name the revision they started from; a stale save gets `409 DRAFT_CONFLICT` (who saved, when) and the designer offers "load theirs" or "keep mine". There is no live co-editing and no edit lock. Draft history is the undo stack in the browser; durable history is the published versions.                                                                                                                                                                                                              | Decided in review (optimistic locking). Designers must never lose work to a validation error.                                                                                                                                 |
| L27 | **Published versions are immutable**, enforced by a database trigger: only `status` may change, and only from `published` to `retired`; versions cannot be deleted. Publishing the same content twice is refused (`NOTHING_TO_PUBLISH`).                                                                                                                                                                                                                                                                                                                                                          | Spec §4.4: interviews stay bound to the version they started with.                                                                                                                                                            |
| L28 | **Breaking changes need a mapping before publishing.** Detected against the last published version: removed variables (rename to a new variable of the same type, or drop), type changes and roster moves (drop), removed codes (recode each old code to a new one or discard), removed grid rows (drop). Added variables and codes are never breaking. The mapping is stored with the new version for exports.                                                                                                                                                                                   | Decided in review ("detect and require mapping"). Matches the spec's explicit mapping step.                                                                                                                                   |
| L29 | _Superseded by L35._ **The condition builder covers flat conditions**: comparisons, `in`/`not in`, `between`, `answered`/not, `contains`, `isDK`, `isRefused` on a variable or `case.*`/`respondent.*` field, joined by all _or_ any. Mixed and/or nesting, arithmetic and other functions are edited as expressions, with live syntax and unknown-variable checks.                                                                                                                                                                                                                               | Decided in review. Covers most skips and filters while keeping the stored form a plain expression.                                                                                                                            |
| L30 | **Every saved scenario must pass to publish.** Scenarios move from browser storage (slice 3 preview) to the server for stored questionnaires; the sample preview keeps browser storage.                                                                                                                                                                                                                                                                                                                                                                                                           | Spec §5.3: scenarios run as regression tests on every publish.                                                                                                                                                                |
| L31 | **Outline is a keyboard tree without drag-and-drop**: arrows, Alt+arrows to reorder and indent, Insert, Delete (undoable), Ctrl+D, F2, Enter. Drag-and-drop can be added later on top of the same tree edits.                                                                                                                                                                                                                                                                                                                                                                                     | Decided in review ("outline + editor panel"); keyboard-first and accessible from the start.                                                                                                                                   |
| L32 | **Renaming a variable rewrites references**: expressions, pipes in texts, skip targets and script anchors. Ids of new questions equal their variable name.                                                                                                                                                                                                                                                                                                                                                                                                                                        | Avoids broken logic after a rename; expressions are text, so a rename would otherwise orphan them.                                                                                                                            |
| L33 | Draft saves are audited at most **once per editor and questionnaire every 5 minutes** (renames always). Creation, publishing, retiring and scenario changes are always audited.                                                                                                                                                                                                                                                                                                                                                                                                                   | Autosave would otherwise flood the audit log with one entry per pause in typing.                                                                                                                                              |
| L34 | Server messages are translated in the client: API errors by their `code`, publish checks (mapping problems, scenario checks, diagnostics) by message id. The server's English text is the fallback.                                                                                                                                                                                                                                                                                                                                                                                               | Changed in review (was: English only).                                                                                                                                                                                        |
| L35 | **The condition builder edits a tree**: nested all/any groups (also "none of" / "not all of"), each condition comparing a variable, `case.*` field or function (`today`, `age`, `count`, `length`, `sum`, `min`, `max`, `datediff`, `round`, `abs`, `rosterCount`) with a value, another variable or a function. Arithmetic and other functions stay in the expression editor. The stored form is still the expression text. A plain-language summary (shared with the paper form, now in `@wansurvey/logic`) and a "Try it" panel that evaluates with the real engine sit under every condition. | Requested after slice 4. Keeps one source of truth (the expression) while covering almost every real skip and filter visually.                                                                                                |
| L36 | **The routing map and the outline's skip arcs are derived** from `routingMap(questionnaire)` on every change; nothing about the drawing is stored. Every arrow is also written out as text in its card or badge, and the drawings are `aria-hidden`.                                                                                                                                                                                                                                                                                                                                              | The map can never drift from the logic, and screen-reader users get the same information.                                                                                                                                     |
| L37 | **Drag and drop in the outline** moves rows before, after or into a section, block or roster (`tree.moveTo`). Invalid places (a block into itself, an item outside a section, a section inside an item) show no marker. Keyboard reordering stays the primary path.                                                                                                                                                                                                                                                                                                                               | Proposal accepted in review. One pure move function serves both.                                                                                                                                                              |
| L38 | **Translations go out as CSV or XLIFF 2.0 and come back with a preview.** Texts are keyed by item id plus field, option code, check id or mode (e.g. `Q1.option.2`), so reordering does not break a file. Empty cells never erase a text; unknown keys and languages the questionnaire does not use are listed and skipped; the import applies as one undoable change.                                                                                                                                                                                                                            | Proposal accepted in review. Keys from ids are stable across drafts; XLIFF 2.0 is what translation tools read.                                                                                                                |
| L39 | **Version comparison matches items by id** and lists added, removed, edited and moved ones. Moves are the minimum set (outside the longest run kept in order), so one moved item does not mark its neighbours. Texts are compared per language, options and rows by code, checks by id, and logic is shown both in plain language and as the expression.                                                                                                                                                                                                                                          | Proposal accepted in review. Reviewers see exactly what changed before approving.                                                                                                                                             |
| L40 | **Comments are threads on an item or the whole questionnaire**, one level of replies, resolved per thread; a reply reopens a resolved thread. Authors delete their own comments while nobody has replied. A new `questionnaires.comment` permission goes to supervisors, reviewers and client viewers (who also get `questionnaires.read`).                                                                                                                                                                                                                                                       | Proposal accepted in review: review rounds with clients without e-mailing documents.                                                                                                                                          |
| L41 | **The question library is per organisation** and holds one item, block or roster with its answer sets. Readers of questionnaires browse it; editors add to it. Inserting renames clashing ids and variables (and references inside the entry) and reuses identical answer sets, renaming different ones.                                                                                                                                                                                                                                                                                          | Proposal accepted in review. Entries are copies: a later library change does not alter questionnaires already using it.                                                                                                       |
| L42 | **Co-editing is light**: presence by heartbeat (5 s, gone after 30 s), notices instead of locks, and a three-way merge by item id when a newer draft arrives. Only the same thing changed differently on both sides (or an edit to something the other side deleted) asks the person which to keep. Undo history is cleared after a merge, since older steps lack the other person's edits.                                                                                                                                                                                                       | Decided in review ("lighter co-editing") over real-time operational transforms: drafts already autosave every 1.5 s, so conflicts are rare and per-item merges cover them.                                                    |
| L43 | **Questionnaires are written and conducted in Spanish.** New questionnaires and projects start in Spanish only, and the demo questionnaires are Spanish only. Another language is added explicitly; the designer then edits **one language at a time** ("Questionnaire language" switch), and interviews show one language at a time with a switch on the interviewer screen. Each added language must be complete before publishing (L13); special-code labels default to No sabe / No responde / No aplica.                                                                                     | Asked for after slice 6: interviews are in Spanish, and translations are separate, deliberate work rather than side-by-side fields.                                                                                           |
| L44 | **Respondents (CAWI) see the runner's buttons and messages in the questionnaire's language** (Siguiente, Anterior, validation messages…). Interviewers in CATI, CAPI and PAPI entry keep the interface language they chose around the questionnaire's texts.                                                                                                                                                                                                                                                                                                                                      | Asked for after L43: a respondent sees one language throughout; staff may work in their own interface language.                                                                                                               |

## Cases and assignments

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Why                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | **Imports are staged.** Parsed rows wait in `sample_import_rows` between upload, mapping and commit; uncommitted imports expire after 24 hours. Commit runs in one transaction and re-validates.                                                                                                                                                                                                                                                                                                                                            | Validation before commit (spec §8.1) without re-uploading, and an import never half-applies.                                                                                     |
| C2  | **Phones are normalised lightly** to E.164 (digits, `00` → `+`, a default country code for national numbers, 7–15 digits) without a full numbering-plan library.                                                                                                                                                                                                                                                                                                                                                                            | Catches obviously wrong numbers now; precise per-country validation can come with CATI dialling (slice 7).                                                                       |
| C3  | **Assignment rules are expressions** over `case.*`, `status`, `priority` and `modePreference`, edited with the same condition builder and evaluated by the logic engine. A quota caps the cases the person holds. Rules apply oldest first, to unassigned fresh cases, on import (not in pool mode) and on request. Each `assignments.kind` is handled by an `AssignmentStrategy` (`apps/api/src/cases/strategies.ts`) that only plans; `rule` is the only one now.                                                                         | One expression language everywhere; spec §3 "case filter or case list". Oldest-first confirmed in review; other algorithms (balanced load, geography) plug in as new strategies. |
| C4  | **Personal data is masked at the API.** Lists show `•••` for sample fields marked personal and for contacts, except as in C4b. A per-case reveal needs `pii.view` and writes `case.pii_viewed` to the audit log. Search over personal fields is only possible with `pii.view`.                                                                                                                                                                                                                                                              | Spec §7 and §12: masking for roles without PII permission, and every PII view audited.                                                                                           |
| C5  | **One person holds a case at a time**, limited to active members whose role conducts interviews or keys data in that project. It only changes hands by reassignment, or in **pool mode** (project setting `assignmentMode: 'pool'`) when a free case is taken: `POST …/cases/:id/claim` assigns it with a conditional update, so of two simultaneous claims one gets 409 `ALREADY_TAKEN`. The holder (or someone with `cases.assign`) can give a case back before it is started. Finished and withdrawn cases are never reassigned in bulk. | Keeps ownership clear for the runtime and offline checkout (slices 6 and 8). Pool mode was asked for in review; device checkout comes in slice 8.                                |
| C6  | **Offset pagination** (25–200 per page) with counts per status; rule filters are evaluated on the server over the narrowed set.                                                                                                                                                                                                                                                                                                                                                                                                             | Simple and adequate for projects up to the 200,000-row import limit; keyset paging can replace it if lists get slow.                                                             |
| C7  | **Case history** (`case_events`) is append-only, enforced by a trigger, and never stores personal values (audit entries for edits list field names only).                                                                                                                                                                                                                                                                                                                                                                                   | Spec §12: immutable history of reassignments and edits.                                                                                                                          |
| C8  | **Reviewers see the interview form only**: answers, including questions marked personal, because they belong to the form; never sample data or contacts. Their role has no `pii.view` and no case access.                                                                                                                                                                                                                                                                                                                                   | Decided in review.                                                                                                                                                               |
| C9  | **Reviewer corrections are suggestions** (slice 11): a `correction_suggestions` row per answer keeps the original value, the suggestion, the reviewer and a status. ## Telephone interviewing (CATI)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Why                                                                                                          |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| K1  | **Queue order**: callbacks and appointments due now (the caller's own first, then those open to anyone), then cases never tried, then due retries; by priority inside each group, then the longest-waiting. A case is eligible when it is not finished, has a valid phone, is the caller's (or free, in pool mode), is not being called by someone else, is due, has attempts left (callbacks are kept past the limit) and it is inside calling hours for the respondent. Cases in an open interview of another mode are left out. The order is a pure function (`apps/api/src/cati/queue.ts`) with unit tests.                                                                                                                             | Spec §6.2. Promised callbacks matter most to respondents; a pure function is easy to test across time zones. |
| K2  | **Locks**: `next` locks the chosen case to the caller for 20 minutes (4 hours once answered, while the interview runs) and opens a call. Candidates are read without locking; only the chosen row is taken with `FOR UPDATE SKIP LOCKED`, so callers working at the same moment get different cases. One request per caller at a time (advisory lock), and a caller's open call comes back from `next` and `current` until it has an outcome or is given back.                                                                                                                                                                                                                                                                              | No case is served twice; a reload or a crash does not lose the call.                                         |
| K3  | **The respondent's time zone** is the case's sample field `timezone` when it is a valid IANA name, otherwise the project's. Calling hours (default 09:00–21:00; the same time twice means all day) apply in that zone, both to the queue and to booking callbacks. The callback picker works in the respondent's time.                                                                                                                                                                                                                                                                                                                                                                                                                      | Interviewers and respondents are often in different zones.                                                   |
| K4  | **Outcome → disposition**: answered → the interview decides; no answer → NO_ANSWER, busy → BUSY, answering machine → ANSWERING_MACHINE (retry after 2 h, 15 min and 4 h by default); wrong number → WRONG_NUMBER and number not in service → DISCONNECTED (final); refused → REFUSAL (final); callback and appointment → CALLBACK at the booked time, for the caller or for anyone. The last allowed attempt without contact ends the case as NON_CONTACT. An answered call whose interview stops early ends as a callback (the interview stays open and resumes on the next call) or as a break-off (BREAK_OFF; the interview is closed as broken off). Submitting a telephone interview closes its call with the interview's disposition. | AAPOR codes from `DISPOSITIONS`; the table is in `packages/schema/src/cati.ts`.                              |
| K5  | **Callers see the numbers of the case they are calling**, whatever the personal-data setting, and the first time a caller is shown a case it is recorded in the audit log (`case.pii_viewed`, automatic). Other sample data follows the project's personal-data rules.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | They cannot dial without the number; the audit keeps who saw what.                                           |
| K6  | **Call history keeps only the last 4 digits** of the number dialled (`••4321`), the outcome, the times, the note and who called. Calls are append-only once they have a disposition (database trigger).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | The history is shown widely (case drawer, review); the full number stays in the contacts only.               |

## Hardening

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Why                                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| H1  | **Field-level encryption of personal sample fields**: fields marked personal are kept out of `cases.sample` in `sample_pii`, one AES-256-GCM sealed JSON object per case, with keyed hashes (HMAC-SHA-256, key derived by HKDF) of each word in `sample_pii_index` so people with `pii.view` can still find a case by a whole name. Reads merge both; writes (import, edit) seal; an hourly job seals anything left in plain text (older data, a field newly marked personal). Contacts stay in plain text, protected by RLS, masking and disk encryption: dialling, e-mailing and duplicate detection need them. | Spec §12; a database dump or a query with the wrong grants no longer shows names.      |
| H2  | **Retention per project**: after `retention.anonymiseAfterDays` from a case's last change (finished or withdrawn only), the nightly job removes personal sample fields, contacts, answers to questions marked personal (with their history), notes, the case copy kept with each interview, call notes and invitation addresses. Non-personal answers stay. Answer history stays append-only: the one change allowed is blanking values, by a security-definer function and a trigger that refuses anything else.                                                                                                 | Spec §12 GDPR: data kept no longer than needed, statistics preserved.                  |
| H3  | **Data subject requests by case**: a JSON export of everything held (sample, contacts, interviews, calls, invitations, history, when staff looked at it) for people with `pii.view` and `cases.read_all`; erasure (as H2, with the request reference) for people with `pii.view` and `cases.edit`. | H5  | **Personal answers stay out of tabulations and of exports for people without `pii.view`**, as the questionnaire schema promises.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Results and client links never carry personal answers.                                 |
| H6  | **A size budget for the respondent page** (240 KB gzipped, entry plus route and its static imports), checked in CI after the build.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | CAWI first load on 4G (spec §12) depends mostly on bytes; growth becomes a decision.   |
